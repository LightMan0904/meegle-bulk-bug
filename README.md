# 飞书项目 · 批量建单器

**当前版本：V1.3**（2026-11-27） · [版本记录](CHANGELOG.md)

> 场景：空间管理员不给开「Excel 导入」权限，但你要一次录几十上百条缺陷/需求。
> 思路：用**你自己的飞书账号**授权飞书项目官方 CLI，走 OpenAPI 逐条创建工作项。

两种用法，共用同一套字段解析逻辑：

| 形态 | 入口 | 适合 |
|---|---|---|
| **图形界面（推荐）** | 双击 `start_gui.bat` → 浏览器操作 | 自己日常用、给同事用 |
| 命令行 | `python meegle_bulk.py ...` | 定时任务、脚本化、批量运维 |

## 一、图形界面

### 启动

```powershell
# 双击 start_gui.bat 也行（会自动装 openpyxl）
python webapp/server.py
```

浏览器会自动打开 `http://127.0.0.1:8765/`（端口被占用会自动顺延）。
服务只监听 127.0.0.1，数据不出本机；Ctrl+C 关闭。

> `start_gui.bat` 会**先结束残留的旧实例**再启动 —— 旧进程占着端口时，浏览器会连到旧代码，
> 表现就是“改了没生效”。也可以手动运行 `stop_gui.bat`。

### 登录：点「扫码登录」，网页里扫二维码

第一次用点页面上的 **「扫码登录」**，会弹出大二维码（260px，白底黑码，手机能直接扫）：

![扫码登录](docs/login.png)

- 二维码用 `verification_uri_complete` 生成，**手机飞书扫码即带上验证码**，确认授权后页面自动变成「登录成功」，无需回终端操作
- 扫不出来时：点「在浏览器打开授权页」，手动输入下面的大号验证码（形如 `XXXXX-XXXXX`）
- 支持切换「飞书项目（中国）/ Meegle（国际版）」
- 二维码 30 分钟有效，过期点「刷新二维码」

> 为什么不用终端里的二维码：Windows 旧控制台把二维码画成半块字符，宽高比失真，手机基本扫不出来。
> 所以这里由网页生成图片，不依赖终端渲染。
>
> 命令行用户仍可用（`--host` 可跳过英文 host 菜单）：
> `npx -y @lark-project/meegle@latest auth login --device-code --host project.feishu.cn`

### 界面流程

1. **连接账号**：扫码登录，或点「检查登录状态」显示你的名字即成功。
2. **选择空间与类型**：空间 key 可从下拉里选（自动列出你有权限的空间），加载类型 → 选 BUG/需求/任务 → 加载字段。
3. **字段与模板**：按 BUG 创建页的 22 行（含 5 个关联字段、解决人角色）展示，顺序与页面一致；
   每行 ↑↓ 可调，顺序保存在 `layouts/<空间>__<类型>.json`，模板跟着变。
   模板：**必填红表头 + `*`、选填蓝表头、附件灰表头（不可导入）**，列宽按字段类型固定（标题 30 / 描述 55 / 下拉 16 / 关联 20…），不会所有列都被拉长。
   9 个选项字段全部带下拉（含机型的 137 个末级、问题管理类型的 6 个可用流程），选项放隐藏「选项」sheet + 名称管理器，不受 Excel 255 字符限制。
4. **上传数据**：拖入 `.xlsx` 或 `.csv`，多工作表可切换。
5. **列映射**：自动把表头对到字段，对不上的手工选；必填项缺失会实时提示。
6. **校验**：只读不写，逐行指出「枚举值不合法 / 必填为空 / 人员找不到」。
7. **执行**：默认**预演**（只打印不创建）；确认后取消勾选「预演模式」再跑。解决人角色在**建单成功后**通过 `role_operate` 写入；订单号/出现bug程序留空会自动填「无」。

### 关联字段：在网页里搜，不用手抄工作项 ID

Excel 里「关联研发工单 / 关联项目 / 关联一级子项目 / 关联缺陷单 / 关联部品认定」可以**整列留空**：

1. 上传并完成列映射后，页面会多出「**关联字段**」卡片
2. 每个格子里输入关键字（标题片段），会实时搜索该关联字段**目标工作项类型**里的真实工作项
3. 选中后自动填成工作项 ID，校验和执行都会用这个 ID
4. 也可以直接在 Excel 里填 ID；网页选择会覆盖 Excel

> 搜索走飞书项目 MQL（`name LIKE '%关键字%'`，最多 20 条）；关联字段的目标类型来自字段元数据
> `related_work_item_info`，不需要手配。多选关联（如关联研发工单）可以在网页里填多个 ID，用逗号分隔。
>
> **性能**：每个关联字段的目标列表会在「加载字段」时后台并行预热并缓存 10 分钟；网页端再缓存一份，
> 输入关键字直接本地过滤。实测聚焦下拉 0ms，只有缓存未命中的关键词才会回源（约 1 秒）。
> 本机已全局安装 `meegle` CLI（`npm i -g @lark-project/meegle`），避免每次调用 `npx` 的启动开销；
> 同事机器建议也装一次。

### 字段会跟着空间配置动态更新

- 点「加载字段」：10 分钟内复用缓存；点 **「刷新字段」** 强制重新拉取
- 管理员改了**字段名 / 必填 / 下拉选项** → 刷新后网页和模板同步更新（模板重新下载即可）
- 管理员**新增创建字段** → 刷新后自动出现在字段清单末尾，标「新增」
- 管理员**删除字段** → 刷新后自动跳过，并在提示里说明
- 顺序、必填、说明、默认值存在 `layouts/` 里，换浏览器/给同事用都一致
- 布局按空间的**真实 project_key** 保存（如 `your-project-key`）；URL 里的短名（`your-space-key`）自动兼容
- **按「测试单类型」动态必填**：一行一个类型（新产品/升级单/出货单），校验时逐行读取该行类型，
  套用该类型的必填集合；创建时按类型做前置自检
- 必填集合不是写死的：刷新字段时对每种类型发一次**安全探测请求**（只带标题+模板+类型，故意缺字段，
  不会建单），从报错里解析必填字段，缓存 24 小时到 `profiles/`；管理员改联动规则后点「刷新字段」自动更新
- 模板是 24 列并集（含测试性质/用例版本），「填写说明」里有一张**按类型必填矩阵**；红表头只标
  “所有类型都必填”的字段，其余按矩阵判断

> 限制：飞书接口不返回“哪些可选字段显示在创建页”，所以**新增的非必填字段**不会自动识别；需要加到 `layouts/*.json`（或告诉我加）。必填新字段会自动带出来。

### 给同事用的三种方式

| 方式 | 做法 | 评价 |
|---|---|---|
| **发文件夹（推荐）** | 整个目录打包发过去 / 放公司 Git，每人自己 `auth login` + 双击 bat | 每人身份独立，审计清晰，零改造成本 |
| 打包 exe | `pip install pyinstaller` 后 `pyinstaller -F -w --add-data "webapp/static;webapp/static" webapp/server.py` | 同事免装 Python；但**仍需 Node.js + meegle CLI**，且要自己登录一次 |
| 部署成共享服务 | 一台机器跑 server，全组访问 | **不推荐**：服务端只有一份登录态，所有单据都记在部署者头上，出了数据问题说不清 |

> 一句话：**工具可以共享，登录态不能共享**。每人扫码一次，是最省事也最合规的方式。

### 通用性

- 空间、工作项类型、字段全部**运行时从你们空间读取**，不写死任何字段名
- 支持需求 / 缺陷 / 任务 / 迭代 / 自定义工作项
- 字段类型：文本、多行文本、单选、多选、人员、日期、数字、关联工作项等
- 表头随便写（「Title」「标题」「BUG标题」都行），映射界面上能改

## 三、为什么这条路走得通

飞书项目开放平台有两种凭证：

| 凭证 | 怎么来 | 是否需要管理员 |
|---|---|---|
| `plugin_token`（插件身份） | 在开放平台建插件，再装到空间 | **要**，装插件是管理员动作 |
| 用户 OAuth 身份 | 用户本人扫码授权 | **不要**，授权即代表你本人 |

官方开源 CLI [`@lark-project/meegle`](https://github.com/larksuite/meegle-cli)（MIT）走的是**用户 OAuth**：
`auth login` 扫码后，所有调用都以你的身份、你的权限执行。

所以：

- ✅ 不需要空间管理员开「Excel 导入」权限
- ✅ 不需要建插件、不需要任何 secret
- ⚠️ 仍受**你在空间里的权限**约束：没有建单权限、字段没有编辑权限，API 一样会拒
- ⚠️ 创建者是你本人，会正常触发通知、拉群、流程

这不是"绕过权限"的黑客手段，而是把**你本来就能手工做 100 次的动作**变成脚本做 100 次。
合不合规看公司内控，建议先跟 TL / 空间管理员打个招呼。

### 和另外几条路比

| 方案 | 需要管理员 | 稳定性 | 附件 | 开发量 | 建议 |
|---|---|---|---|---|---|
| 官方 Excel 导入（新建▼→Excel 导入） | 要（开权限或代导） | 最高 | 不支持 | 0 | **首选** |
| **本工具（CLI + OAuth）** | 不要 | 高（走 OpenAPI） | 支持（二次上传） | 已写好 | **次选**，可长期复用 |
| 自研直连 OpenAPI | **要**（plugin_token 要装插件） | 高 | 支持 | 中 | 不划算 |
| Playwright / RPA 点页面 | 不要 | 低（改版就崩） | 支持 | 中 | 不建议 |

## 四、表头与字段规则

- 模板只包含**创建表单字段**：`meta-fields` 会把详情页、流程节点里的字段也返回（几十上百个），
  但建单只认创建表单那一份，所以工具用 `meta-create-fields` 过滤；附件/投票/计算字段不可写，也一并排除
- **顺序**：创建页 `.../wenti/create` 需要登录态，工具抓不到页面本身；字段与顺序取自创建表单的元数据
  （页面渲染用的同一份配置）。如果和你看到的顺序有出入，用字段表右侧 ↑↓ 调一次，模板会按调整后的顺序生成
- 第一行表头，从第二行起一行一条；红色表头带 `*` 的是必填
- **下拉选项怎么和飞书项目对上**：模板里存的是选项**文字**（label），工具创建时用 `meta` 里的
  `label → option_id` 映射换成 id 再调 API；多选用 `、,;/` 分隔后逐个换；级联选择取**末级**选项的 id。
  所以只要文字与空间里的选项完全一致就能对上，对不上会直接报「不是 xxx 的合法选项」
- 下拉来自「选项」隐藏 sheet + 名称管理器，所以选项几十个也能下拉（Excel 内联列表有 255 字符上限）
- **解决人**是流程角色（`role_xxx`），不是普通字段：Excel 填姓名/邮箱，建单成功后调
  `workitem update --role-operate` 写入；失败会在结果表里标出来，不会静默丢
- **附件**列保留但不可导入（灰表头 + 批注 + 说明页都写了），填了也会被忽略
- **订单号 / 出现bug程序** 留空自动填「无」；关联字段填工作项 ID，多个用逗号分隔
- 枚举列必须填下拉里的值（大小写、空格要一致）
- 人员列填姓名或企业邮箱，工具自动 `user search` 换 userkey（缓存到 `users.json` / `.cache_users.json`）
- 关联类字段（关联研发工单 / 关联缺陷单）一般填**工作项 ID**，不是标题
- 附件列即使填了也会忽略：附件走两阶段上传，建单后再用 `meegle attachment +upload` 补

## 五、常见报错

| 报错 | 原因 / 处理 |
|---|---|
| 未登录 / no local token | 页面点「扫码登录」重新扫一次（或命令行 `auth login --device-code --host project.feishu.cn`） |
| `workitem type not found` | 类型 key 写错，界面上重新「加载类型」 |
| 缺少必填字段 | 映射里没对上，或该列整列为空 |
| 不是 xxx 的合法选项 | 枚举值和空间配置不一致，重新下载模板 |
| `10429 / 429 / 请求过于频繁` | 已自动退避重试；仍失败就把「每条间隔」调大 |
| `403 / no permission` | 你本人没有建单/字段权限，API 也救不了 |
| template 字段必填 | 执行页选「流程/模板」，或 `config.template_name` |
| `ErrFieldRequired ... 解决人(role_<pk>_<type>_role_xxx) 必填` | 解决人是**创建时必填的角色**：必须在 create 的 `role_owners` 里写入，且 `role` 用 meta-roles 的**裸 role_id**（`role_xxx`）；写复合 key 会被拒。建单后再 update 来不及 |
| `ErrCascadeFieldValueDepthInvalid / 级联选项字段值层级无效` | 机型这类 `tree-select` **不能传裸 option_id**，必须传 **stringified 的「根→叶」option 对象数组**：`[{"option_id":"<根>"},{"option_id":"<叶>"}]`（工具已自动生成） |
| `ErrFieldRequired ... 关联项目(field_xxx) 必填` | 关联项目在页面上没有星号，但**接口必填**；模板里已标红，需填关联项目的工作项 ID |
| 下载模板得到 `latin-1 codec can't encode` | 旧版 bug：中文文件名写进 HTTP 头。重启 `start_gui.bat` 即修复（文件名按 RFC 5987 编码） |

## 六、建议的使用姿势

1. **先灰度 3~5 条**：预演 → 真跑 5 条 → 到页面确认字段/流程都对。
2. **再全量**：中途停止也没关系，`state.json` 记住进度（CLI 版）。
3. **通知会炸**：每条都可能触发飞书通知/拉群，几百条建议分时段或临时调通知规则。
4. **回滚成本高**：飞书项目没有批量删除，删错要逐条删。务必先灰度、留结果台账。
5. **别共享 token**：CLI 凭证在系统钥匙串里，等于你的账号。

## 十、发布新版本（维护者）

1. 改 `VERSION`、`CHANGELOG.md`，同步说明文档封面版本号。
2. 生成干净发布包：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\release.ps1
   ```

   输出 `dist/meegle-bulk-bug-vX.Y.zip`，自动排除缓存/日志/测试文件，并生成 `dist/SHA256.txt`。
3. 提交并打 tag：`git tag vX.Y`、`git push --tags`。
4. 建 Release：`gh release create vX.Y dist/meegle-bulk-bug-vX.Y.zip -F CHANGELOG.md`，或网页手动上传。
5. 同事只下载 Release 里的 zip，解压覆盖旧目录；`logs/`、`profiles/`、`layouts/` 保留即可。
